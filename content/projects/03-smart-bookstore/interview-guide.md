# 面试指南

## 1. 5 分钟讲清项目结构

### 一句话概括
"这是一个基于 Spring Cloud Alibaba 的分布式秒杀系统，通过一次秒杀下单串联了 12 项分布式核心技术。"

### 讲述框架
1. **项目定位**：企业级分布式技术学习案例
2. **技术栈**：Spring Cloud Alibaba 全家桶（Nacos + Dubbo + Sentinel + Seata + RocketMQ）
3. **核心链路**：秒杀下单的 12 个技术点
4. **亮点**：Redis 预减库存 + Seata 分布式事务 + ShardingSphere 分库分表

## 2. 高频面试题

### Q: 如何防止超卖？

三层防护：
1. **Redis 预减库存**：Lua 脚本原子扣减，内存操作高性能
2. **分布式锁**：Redisson 防止同一用户并发请求
3. **数据库乐观锁**：版本号机制兜底，CAS 更新

### Q: 如何保证数据一致性？

- **Seata AT 模式**：订单创建和库存扣减在同一个全局事务中，任一失败自动回滚
- **消息队列 + 幂等**：MQ 异步削峰，消费端 Redis SETNX 保证幂等
- **最终一致性**：非关键路径通过消息队列解耦，允许短暂不一致

### Q: 如何应对高并发？

多级防护策略：
1. **网关限流**：Sentinel 网关流控，10000 QPS 上限
2. **服务限流**：Sentinel 服务级 + 热点参数限流
3. **异步削峰**：RocketMQ 将 10000 QPS 削峰为 500 QPS 平稳消费
4. **快速失败**：限流触发时直接返回"系统繁忙"

### Q: 分库分表怎么做？

- **分片键**：订单表按 user_id 分片，库存表按 product_id 分片
- **分片算法**：`user_id % 2` 分库，`user_id % 4` 分表
- **绑定表**：t_order 和 t_order_item 绑定，避免跨库 JOIN
- **分布式 ID**：雪花算法生成全局唯一订单号

### Q: 分布式锁怎么实现的？

基于 Redisson：
- `@DistributedLock` 注解声明式使用
- 看门狗机制自动续期（默认每 10 秒续期一次）
- 支持可重入、读写锁
- 配合 Lua 脚本保证原子性

### Q: 为什么选 Dubbo 而不是 Feign？

- **性能**：Dubbo 基于 TCP 长连接，比 HTTP 短连接性能更好
- **负载均衡**：内置多种策略（随机、轮询、最少活跃等）
- **服务治理**：完善的熔断、重试、超时控制

### Q: Seata AT 模式的原理？

1. **第一阶段**：执行业务 SQL，记录 undo_log（包含前后镜像）
2. **第二阶段**：全局提交时删除 undo_log；全局回滚时根据 undo_log 自动补偿

优势：对业务代码侵入小，只需 `@GlobalTransactional` 注解。

### Q: MQ 消息丢失怎么处理？

- **生产端**：同步发送 + 重试机制，RocketMQ 同步刷盘
- **消费端**：手动 ACK，消费失败重试
- **兜底**：定时任务补偿，核对订单状态

## 3. 面试官深度追问应对

### 追问：如果 Redis 挂了怎么办？

多级容错：
1. Redis 集群（Sentinel/Cluster）保证高可用
2. 降级方案：限流直接返回，或降级为数据库操作
3. 兜底：数据库乐观锁保证最终正确性

### 追问：Seata 的性能瓶颈？

- AT 模式需要记录 undo_log，额外的一次 SQL 写入
- 全局锁会降低并发性能
- 优化方案：缩短事务范围，非关键路径不参与全局事务

### 追问：如何优化秒杀系统？

- **页面静态化**：商品详情页 CDN 缓存
- **浏览器/客户端限流**：按钮置灰、倒计时
- **预加载**：活动开始前预热缓存
- **队列泄洪**：MQ 削峰填谷
- **弹性伸缩**：K8s 自动扩缩容

### 追问：分布式 ID 怎么生成的？

- 使用雪花算法（Snowflake）
- 组成：1bit 符号位 + 41bit 时间戳 + 10bit 机器位 + 12bit 序列号
- 趋势递增、高性能、全局唯一

## 4. 亮点表达

- **"使用责任链模式实现校验链"**：可插拔、易扩展、职责单一
- **"Lua 脚本保证库存操作原子性"**：减少网络往返，避免竞态条件
- **"Seata AT 模式低侵入"**：一个注解完成分布式事务
- **"异步削峰 + 快速失败"**：用户体验和系统稳定性兼顾
- **"分库分表透明化"**：ShardingSphere-JDBC 对业务代码零侵入
