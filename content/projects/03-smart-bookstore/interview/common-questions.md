# 高频面试题

> 50+ 道技术问题及参考答案

## 基础篇

### Q: 微服务架构的优缺点？
**优点**：
- 独立部署、独立扩展、技术异构
- 故障隔离、团队自治

**缺点**：
- 分布式复杂性（网络延迟、数据一致性）
- 运维成本高（监控、日志、部署）

### Q: Spring Cloud Alibaba 和 Spring Cloud Netflix 的区别？
- Nacos 替代 Eureka（支持配置中心）
- Sentinel 替代 Hystrix（更丰富的限流策略）
- Dubbo 替代 Feign（TCP 长连接性能更好）
- Seata 替代 2PC（AT 模式低侵入）

### Q: Nacos 作为注册中心和配置中心的原理？
- **注册中心**：服务启动时向 Nacos 注册，心跳检测健康状态
- **配置中心**：长轮询机制，配置变更实时推送
- **AP 模式**：保证可用性和分区容错性

### Q: Dubbo 的服务调用过程？
1. 服务提供者启动，注册到 Nacos
2. 服务消费者订阅，获取提供者列表
3. 消费者根据负载均衡策略选择节点
4. 通过 Netty 发起 TCP 调用
5. 提供者执行并返回结果

## 秒杀篇

### Q: 如何防止超卖？
**三层防护**：
1. **Redis 预减库存**：Lua 脚本原子扣减，内存操作高性能
2. **分布式锁**：Redisson 防止同一用户并发请求
3. **数据库乐观锁**：版本号机制兜底

### Q: 库存扣减为什么用 Lua 脚本？
- **原子性**：多条 Redis 命令一次执行
- **减少网络往返**：一次网络请求完成检查和扣减
- **避免竞态条件**：脚本执行期间不会被其他命令中断

### Q: 为什么先写 Redis 再写数据库？
- Redis 是内存操作，性能高，适合做前置过滤
- 写数据库失败时可以通过 Seata 回滚 Redis
- 异步削峰：先快速响应，再异步持久化

### Q: 秒杀系统如何优化？
- **前端**：按钮置灰、CDN 缓存、倒计时
- **网关**：Sentinel 限流、IP 黑名单
- **应用**：Redis 预减、MQ 削峰、快速失败
- **数据**：分库分表、读写分离

## 分布式篇

### Q: Seata AT 模式的工作原理？
**第一阶段**：执行业务 SQL，记录 undo_log（前后镜像）
**第二阶段**：全局提交时删除 undo_log；全局回滚时根据 undo_log 自动补偿

### Q: 分布式事务的几种方案对比？
| 方案 | 一致性 | 性能 | 侵入性 |
|------|--------|------|--------|
| Seata AT | 强 | 中 | 低 |
| TCC | 强 | 高 | 高 |
| 可靠消息 | 最终 | 高 | 中 |
| Saga | 最终 | 高 | 中 |

### Q: 分库分表后如何做分页查询？
- **全局查询**：所有分片查询后聚合
- **二次查询**：先查各分片最小值，再定位具体分片
- **禁止跨分片排序**：使用分片键排序避免全量聚合

### Q: 分布式 ID 生成方案？
- **雪花算法**：1bit + 41bit 时间戳 + 10bit 机器位 + 12bit 序列号
- **Redis INCR**：Redis 自增，性能高但需要做持久化
- **号段模式**：一次取一批 ID，本地自增

### Q: Sentinel 的限流算法？
- **滑动窗口**：统计单位时间内的请求数
- **漏桶**：恒定速率处理请求
- **令牌桶**：允许一定程度的突发流量

## 场景篇

### Q: Redis 库存和数据库库存不一致怎么办？
1. **Seata 回滚**：数据库失败时 Redis 自动回滚
2. **定时对账**：定时任务检查 Redis 和 MySQL 库存一致性
3. **最终一致性**：以数据库为准，Redis 作为缓存预热

### Q: 消息丢失怎么处理？
- **生产端**：同步发送 + 重试，RocketMQ 同步刷盘
- **Broker**：主从架构，消息多副本
- **消费端**：手动 ACK，消费失败重试
- **兜底**：定时任务核对订单状态

### Q: 缓存穿透、击穿、雪崩怎么解决？
| 问题 | 现象 | 解决方案 |
|------|------|---------|
| 穿透 | 查询不存在的数据 | 布隆过滤器，空值缓存 |
| 击穿 | 热点 Key 过期 | 互斥锁，热点数据不过期 |
| 雪崩 | 大量 Key 同时过期 | 过期时间随机化，多级缓存 |

### Q: 如何进行压力测试？
- **工具**：JMeter、Locust
- **场景**：秒杀接口压测、下单流程压测
- **指标**：QPS、响应时间 P99、错误率
- **监控**：CPU、内存、GC、网络 IO
