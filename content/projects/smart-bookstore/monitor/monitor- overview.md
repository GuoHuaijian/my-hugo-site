# 📊 BookStore智能监控系统

> 企业级全链路监控解决方案，实时保障系统稳定性与性能

## 🎯 系统概述

BookStore智能监控系统是一个面向微服务架构的企业级监控解决方案，实现了从系统指标、业务指标到链路追踪的全维度监控。

### 核心价值
- **🔍 实时监控** - 毫秒级指标采集，实时掌握系统状态
- **🚨 智能告警** - 多维度告警规则，多渠道通知
- **📈 可视化** - 丰富的图表展示，直观的数据呈现
- **⚡ 性能分析** - 深度性能分析，快速定位问题
- **📊 业务监控** - 端到端业务指标监控

## 📋 功能特性

### 📊 监控能力
- **系统监控** - CPU、内存、磁盘、网络等基础资源
- **应用监控** - JVM、GC、线程、类加载等运行时指标
- **业务监控** - QPS、响应时间、成功率、错误率
- **数据库监控** - 连接池、慢查询、执行效率
- **中间件监控** - Redis、RocketMQ、Nacos等状态监控

### 🔍 追踪能力
- **分布式追踪** - 全链路调用追踪
- **性能分析** - 方法级性能剖析
- **错误追踪** - 异常堆栈自动收集
- **拓扑分析** - 服务依赖关系可视化

### 📈 可视化能力
- **实时仪表盘** - 关键指标实时展示
- **自定义图表** - 灵活的图表配置
- **告警大盘** - 全局告警状态展示
- **业务大屏** - 业务指标可视化展示

## 🚀 快速开始

### 环境要求
- JDK 17+
- Maven 3.6+
- Docker & Docker Compose
- 8GB+ 内存，50GB+ 磁盘

### 一键启动

```bash
# 1. 克隆监控项目
git clone https://github.com/your-repo/bookstore-monitor.git
cd bookstore-monitor

# 2. 启动基础服务
docker-compose up -d

# 3. 等待服务启动
sleep 30

# 4. 启动监控服务
mvn spring-boot:run

# 5. 访问监控面板
open http://localhost:8080/monitor/dashboard
```

### 核心服务地址
| 服务 | 地址 | 说明 |
|------|------|------|
| 监控面板 | http://localhost:8080/monitor/dashboard | Grafana可视化界面 |
| Prometheus | http://localhost:9090 | 指标查询 |
| SkyWalking | http://localhost:12800 | 链路追踪 |
| AlertManager | http://localhost:9093 | 告警管理 |

## 📊 关键指标

### 业务指标
- `seckill.requests.total` - 秒杀请求数
- `seckill.success.rate` - 秒杀成功率
- `order.processing.time` - 订单处理耗时
- `payment.success.rate` - 支付成功率

### 系统指标
- `system.cpu.usage` - CPU使用率
- `system.memory.usage` - 内存使用率
- `jvm.gc.count` - GC次数
- `jvm.thread.count` - 线程数

### 服务指标
- `http.server.requests` - HTTP请求数
- `service.response.time` - 服务响应时间
- `database.query.time` - 数据库查询耗时

## 🔧 监控配置

### 基础配置
```yaml
bookstore:
  monitor:
    # 指标采集间隔
    metrics:
      interval: 5000
      enabled: true

    # 告警配置
    alert:
      enabled: true
      check-interval: 10

    # 健康检查
    health:
      enabled: true
      interval: 30000
```

### 告警规则示例
```yaml
rules:
  - name: "CPU使用率过高"
    metric: "system.cpu.usage"
    condition: ">="
    threshold: 80
    duration: 5m
    level: "WARNING"
    channels: ["webhook", "email"]

  - name: "服务响应时间过长"
    metric: "service.response.time"
    condition: ">"
    threshold: 1000
    duration: 2m
    level: "CRITICAL"
    channels: ["dingtalk"]
```
