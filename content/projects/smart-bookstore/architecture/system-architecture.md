## 3. 设计原则

### 3.1 单一职责
- 每个服务只负责一个业务领域
- 秒杀服务只处理秒杀入口逻辑，不直接操作订单数据库

### 3.2 服务自治
- 每个服务有独立的数据库
- 服务间通过Dubbo RPC调用

### 3.3 接口隔离
- Dubbo接口定义在独立的API模块
- 使用DTO传输，不暴露内部实体

### 3.4 最终一致性
- 使用消息队列解耦
- 通过Seata保证关键操作的强一致性

### 4.1 服务高可用

### 4.2 缓存高可用
- Redis Cluster 或 Sentinel 模式
- 多级缓存：本地缓存 + Redis

### 4.3 消息队列高可用
- RocketMQ 主从架构
- 同步刷盘保证消息不丢失

### 4.4 数据库高可用
- MySQL 主从复制
- ShardingSphere 读写分离

## 5. 容错设计

### 5.1 限流
- 网关层：API级别限流
- 服务层：资源级别限流
- 热点参数：商品ID级别限流

### 5.2 熔断
- 调用失败率超过阈值触发熔断
- 熔断期间快速失败

### 5.3 降级
- 限流触发时返回友好提示
- 服务不可用时返回降级数据

### 5.4 超时
- Dubbo调用超时：5秒
- 数据库操作超时：30秒
- 分布式事务超时：30秒

## 6. 安全设计

### 6.1 认证授权
- JWT Token认证
- 网关统一鉴权

### 6.2 接口安全
- 防重复提交：分布式锁
- 防刷：限流 + 黑名单

### 6.3 数据安全
- 敏感数据加密存储
- 日志脱敏
