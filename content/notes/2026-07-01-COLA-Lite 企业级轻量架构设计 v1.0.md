# COLA-Lite 企业级轻量架构设计 v1.0

## 一、设计背景与目标

### 1.1 我们在解决什么问题？

在企业中后台系统的日常开发中，团队往往面临以下困境：

| 问题 | 表现 | 影响 |
|------|------|------|
| Service 层臃肿 | 单个 Service 动辄数千行 | 难以维护，多人协作冲突频繁 |
| Controller 越权 | 业务逻辑渗透至入口层 | 职责不清，无法复用 |
| 模块循环依赖 | 模块间随意互调 | 牵一发而动全身 |
| 公共逻辑散落 | 通知、权限、审计重复编写 | 维护成本高，行为不一致 |
| 架构选型两难 | 引入 DDD 过度设计 | 不引入又缺乏规范 |

### 1.2 现有方案的局限

```text
完整 COLA    → 分层清晰，但领域建模学习成本高，CRUD 项目难以落地
完整 DDD     → 适合复杂领域，中后台 CRUD 项目严重过度设计
传统三层架构  → 上手快，但无扩展性，Service 必然臃肿
```

### 1.3 COLA-Lite 的定位

**COLA-Lite** 是 COLA 架构的轻量化变体，专为企业中后台 CRUD 场景设计，在保留 COLA 核心分层思想的基础上，移除了领域建模相关复杂度。

**设计哲学：**

```text
取自 COLA        → 清晰的分层思想与职责边界
取自六边形架构    → 统一的外部入口适配设计
取自 CQRS        → 读写职责分离，各自独立演化
保留事件驱动     → 模块间解耦的核心机制

移除 DDD Aggregate Root  → 避免过度设计
移除 DDD Domain Service  → 降低建模复杂度
移除 Event Sourcing      → CRUD 场景无需事件溯源
移除 ACL 防腐层          → 轻量场景过于繁重
```

**一句话定位：COLA 的轻量版，比 MVC 更规范，比 DDD 更易落地。**

### 1.4 适用场景

✅ **推荐使用**

> ERP · OA · CRM · WMS · MES · SaaS 管理平台 · 电商中后台 · 数据管理平台 · AI 运营后台

❌ **不推荐使用**

> 高并发交易核心 · 金融结算系统 · 风控引擎 · 复杂规则引擎

> 上述场景建议采用完整 COLA 或 DDD 架构。

### 2.3 依赖规则

| 模块 | 可依赖 | 禁止依赖 | 说明 |
|------|--------|----------|------|
| `base` | Hutool 等工具库 | Spring、任何业务模块 | 最底层，保持纯净 |
| `support` | `base`、Spring 生态 | 任何业务模块 | 通用能力，无业务含义 |
| `framework` | `support` | `capability`、业务模块 | 技术组件不引入业务概念 |
| `capability` | `framework`、`support` | 业务模块 | 业务组件不引入具体业务 |
| `common` | `capability`、`framework` | 其他任何业务模块 | 公共业务，不被其他业务模块依赖 |
| 其他业务模块 | `capability`、`framework`、`support` | **其他任何业务模块（含 common）** | 通过事件解耦 |
| `app` | 所有模块 | — | 仅做装配，无业务逻辑 |

### 2.4 common 模块说明

```text
common 是公共业务模块，而非公共基础模块。

提供前端各端直接调用的基础业务接口：
  ├── 文件上传 / 下载
  ├── 数据字典查询
  └── 省市区地域数据

其他业务模块（admin、portal 等）禁止代码依赖 common。
若业务模块内部需要字典 / 地域数据，通过 capability 层组件读取，
或由前端自行调用 common 接口后将参数传入。
```

### 3.1 ErrorCode 设计

```java
/**
 * 错误码接口，各模块实现此接口扩展自己的错误码
 * 格式建议：{模块编号}{类型}{序号}
 * 示例：100101 → 用户模块(1001) + 业务错误(0) + 序号(1)
 */
public interface ErrorCode {
    String getCode();
    String getMessage();
}

/**
 * 系统级错误码（base 模块定义，全局通用）
 */
public enum SysErrorCode implements ErrorCode {
    SUCCESS("000000", "操作成功"),
    SYSTEM_ERROR("999999", "系统内部错误"),
    PARAM_ERROR("000001", "参数校验失败"),
    NOT_FOUND("000002", "资源不存在"),
    FORBIDDEN("000003", "无操作权限"),
    UNAUTHORIZED("000004", "未登录或登录已过期");

    private final String code;
    private final String message;

    SysErrorCode(String code, String message) {
        this.code = code;
        this.message = message;
    }

    @Override public String getCode() { return code; }
    @Override public String getMessage() { return message; }
}
```

```java
/**
 * 用户模块错误码（定义在 user 业务包内）
 */
public enum UserErrorCode implements ErrorCode {
    USER_NOT_FOUND("100101", "用户不存在"),
    USER_ALREADY_EXISTS("100102", "用户名已存在"),
    USER_DISABLED("100103", "用户已被禁用"),
    PHONE_ALREADY_EXISTS("100104", "手机号已被注册");

    private final String code;
    private final String message;

    UserErrorCode(String code, String message) {
        this.code = code;
        this.message = message;
    }

    @Override public String getCode() { return code; }
    @Override public String getMessage() { return message; }
}
```

### 3.2 异常体系

```java
/**
 * 所有异常的基类
 */
public abstract class BaseException extends RuntimeException {
    private final String code;
    private final String message;

    protected BaseException(ErrorCode errorCode) {
        super(errorCode.getMessage());
        this.code = errorCode.getCode();
        this.message = errorCode.getMessage();
    }

    protected BaseException(ErrorCode errorCode, String message) {
        super(message);
        this.code = errorCode.getCode();
        this.message = message;
    }

    public String getCode() { return code; }
    @Override public String getMessage() { return message; }
}

/**
 * 业务异常：预期内的业务规则不满足
 * 示例：用户不存在、状态不允许、余额不足
 */
public class BizException extends BaseException {
    public BizException(ErrorCode errorCode) {
        super(errorCode);
    }
    public BizException(ErrorCode errorCode, String message) {
        super(errorCode, message);
    }
}

/**
 * 系统异常：非预期的技术性错误
 * 示例：数据库连接失败、第三方服务超时
 */
public class SysException extends BaseException {
    public SysException(ErrorCode errorCode, Throwable cause) {
        super(errorCode);
        initCause(cause);
    }
}
```

### 4.1 统一响应结构

```java
@Data
public class Result<T> {
    private String code;
    private String message;
    private T data;

    public static <T> Result<T> success() {
        return success(null);
    }

    public static <T> Result<T> success(T data) {
        Result<T> result = new Result<>();
        result.code = SysErrorCode.SUCCESS.getCode();
        result.message = SysErrorCode.SUCCESS.getMessage();
        result.data = data;
        return result;
    }

    public static <T> Result<T> fail(ErrorCode errorCode) {
        Result<T> result = new Result<>();
        result.code = errorCode.getCode();
        result.message = errorCode.getMessage();
        return result;
    }

    public static <T> Result<T> fail(String code, String message) {
        Result<T> result = new Result<>();
        result.code = code;
        result.message = message;
        return result;
    }
}
```

### 4.2 事件基础设施

```java
/**
 * 领域事件基类，所有业务事件均继承此类
 */
@Getter
public abstract class DomainEvent {
    private final String eventId = IdUtil.fastSimpleUUID();
    private final LocalDateTime occurredAt = LocalDateTime.now();
    private final String source;

    protected DomainEvent(String source) {
        this.source = source;
    }
}

/**
 * 事件发布器，封装 Spring ApplicationEventPublisher
 */
@Component
@RequiredArgsConstructor
public class EventPublisher {

    private final ApplicationEventPublisher publisher;

    /** 同步发布（随当前事务） */
    public void publish(DomainEvent event) {
        publisher.publishEvent(event);
    }

    /** 异步发布（与事务无关的通知类场景） */
    @Async
    public void publishAsync(DomainEvent event) {
        publisher.publishEvent(event);
    }
}
```

### 4.3 全局异常处理

```java
@Slf4j
@RestControllerAdvice
public class GlobalExceptionHandler {

    /** 业务异常：符合预期，warn 级别日志 */
    @ExceptionHandler(BizException.class)
    public Result<Void> handleBizException(BizException e) {
        log.warn("业务异常: code={}, message={}", e.getCode(), e.getMessage());
        return Result.fail(e.getCode(), e.getMessage());
    }

    /** 参数格式校验失败（@Valid 触发） */
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result<Void> handleValidationException(MethodArgumentNotValidException e) {
        String message = e.getBindingResult().getFieldErrors()
            .stream()
            .map(FieldError::getDefaultMessage)
            .collect(Collectors.joining("; "));
        log.warn("参数格式校验失败: {}", message);
        return Result.fail(SysErrorCode.PARAM_ERROR.getCode(), message);
    }

    /** 系统异常：非预期，error 级别日志，不暴露内部细节 */
    @ExceptionHandler(Exception.class)
    public Result<Void> handleException(Exception e) {
        log.error("系统异常", e);
        return Result.fail(SysErrorCode.SYSTEM_ERROR);
    }
}
```

## 八、对象模型设计

### 8.1 对象职责总览

| 对象    | 所在位置 | 职责 | 校验方式 |
|-------|----------|------|----------|
| Form  | `application/model/form` | 接收 HTTP 入参，承载格式校验 | `@Valid` 注解 |
| Query | `application/model/query` | 封装读操作查询条件 | 无强制，按需 |
| DTO   | `application/model/dto` | 层间数据传递（Command → Helper，跨组件调用） | 无 |
| VO    | `application/model/vo` | 接口响应数据 | 无 |

## 十一、Command（写操作）

**负责所有会改变系统状态的操作，是事务边界的所有者。**

### 11.1 设计规范

```text
✅ @Transactional 加在 execute 方法上，Command 是事务边界
✅ 接收 Form 直接处理，无需转换为其他对象
✅ 业务规则校验委托给 Helper 中的 Validator
✅ 需要传递数据给 Helper / Capability 时，构建 DTO 传入
✅ 事务提交后发布业务事件
✅ 单个 Command 只处理一种操作意图
❌ Command 不调用其他 Command
❌ Command 不做复杂查询返回（仅返回主键等必要标识）
```

### 11.2 示例

```java
@Slf4j
@Component
@RequiredArgsConstructor
public class CreateUserCommand {

    private final UserValidator userValidator;
    private final UserMapper userMapper;
    private final UserConvert userConvert;
    private final EventPublisher eventPublisher;
    private final NotificationComponent notificationComponent;

    @Transactional(rollbackFor = Exception.class)
    public Long execute(CreateUserForm form) {
        // 1. 业务规则校验（格式校验已由 @Valid 在 Adapter 层完成）
        userValidator.checkUsernameNotExists(form.getUsername());
        userValidator.checkPhoneNotExists(form.getPhone());

        // 2. Form → Model（MapStruct）
        UserModel userModel = userConvert.toModel(form);
        userModel.setPassword(encryptPassword(form.getPassword()));
        userModel.setStatus(UserStatus.ENABLE);

        // 3. 持久化（直接调用 Mapper，简单写操作无需 Repository）
        userMapper.insert(userModel);
        log.info("用户创建成功: userId={}, username={}", userModel.getId(), userModel.getUsername());

        // 4. 构建 DTO 传递给通知组件
        UserDTO userDTO = UserDTO.builder()
            .userId(userModel.getId())
            .username(userModel.getUsername())
            .phone(userModel.getPhone())
            .deptId(userModel.getDeptId())
            .build();

        // 5. 事务提交后发布事件
        registerAfterCommit(() ->
            eventPublisher.publish(new UserCreatedEvent(userDTO))
        );

        // 6. 发送欢迎通知（非核心逻辑，失败不影响主流程）
        sendWelcomeNotification(userDTO);

        return userModel.getId();
    }

    private void registerAfterCommit(Runnable action) {
        TransactionSynchronizationManager.registerSynchronization(
            new TransactionSynchronization() {
                @Override
                public void afterCommit() {
                    action.run();
                }
            }
        );
    }

    private void sendWelcomeNotification(UserDTO userDTO) {
        try {
            notificationComponent.send(NotificationMessage.builder()
                .userId(userDTO.getUserId())
                .phone(userDTO.getPhone())
                .content("欢迎加入系统，您的账号已创建成功。")
                .channels(List.of(NotifyChannel.SMS, NotifyChannel.INNER))
                .build());
        } catch (Exception e) {
            log.warn("发送欢迎通知失败: userId={}", userDTO.getUserId(), e);
        }
    }

    private String encryptPassword(String rawPassword) {
        return BCrypt.hashpw(rawPassword, BCrypt.gensalt());
    }
}
```

## 十二、Query（读操作）

**负责所有查询类操作，不修改任何系统状态。**

### 12.1 设计规范

```text
✅ 不加 @Transactional
✅ 接收 Query（查询条件）直接处理
✅ 简单查询直接调 Mapper
✅ 需要缓存时调 Cache，自行组合 Mapper + Cache
✅ 复杂数据组装委托给 Assembler
❌ 禁止任何写操作
❌ 不调用 Command
```

### 12.2 示例

```java
/**
 * 用户详情查询
 */
@Component
@RequiredArgsConstructor
public class UserDetailQuery {

    private final UserMapper userMapper;
    private final UserCache userCache;
    private final UserAssembler userAssembler;

    public UserVO execute(Long userId) {
        // 自行组合缓存与 Mapper
        UserModel userModel = userCache.get(userId);
        if (userModel == null) {
            userModel = userMapper.selectById(userId);
            if (userModel == null) {
                throw new BizException(UserErrorCode.USER_NOT_FOUND);
            }
            userCache.set(userId, userModel);
        }
        // 复杂组装委托给 Assembler
        return userAssembler.assembleVO(userModel);
    }
}

/**
 * 用户分页查询（简单场景，直接调 Mapper）
 */
@Component
@RequiredArgsConstructor
public class UserPageQuery {

    private final UserMapper userMapper;
    private final UserConvert userConvert;

    public PageResult<UserVO> execute(UserPageForm form) {
        Page<UserModel> page = userMapper.selectPage(
            new Page<>(form.getPageNum(), form.getPageSize()),
            buildWrapper(form)
        );
        return PageResult.of(page, userConvert::toVO);
    }

    private LambdaQueryWrapper<UserModel> buildWrapper(UserPageForm form) {
        return new LambdaQueryWrapper<UserModel>()
            .like(StrUtil.isNotBlank(form.getUsername()), UserModel::getUsername, form.getUsername())
            .eq(form.getStatus() != null, UserModel::getStatus, form.getStatus())
            .eq(form.getDeptId() != null, UserModel::getDeptId, form.getDeptId())
            .ge(form.getStartDate() != null, UserModel::getCreateTime, form.getStartDate())
            .le(form.getEndDate() != null, UserModel::getCreateTime, form.getEndDate())
            .orderByDesc(UserModel::getCreateTime);
    }
}
```

### 13.1 Validator（业务规则校验）

```java
/**
 * 格式校验（@Valid）  → Adapter 层，Spring 自动执行，校验 Form 字段格式
 * 业务校验（Validator）→ Application 层，手动调用，校验业务规则
 */
@Component
@RequiredArgsConstructor
public class UserValidator {

    private final UserMapper userMapper;

    /** 校验用户名不重复 */
    public void checkUsernameNotExists(String username) {
        boolean exists = userMapper.exists(
            new LambdaQueryWrapper<UserModel>()
                .eq(UserModel::getUsername, username)
        );
        if (exists) {
            throw new BizException(UserErrorCode.USER_ALREADY_EXISTS);
        }
    }

    /** 校验手机号不重复 */
    public void checkPhoneNotExists(String phone) {
        boolean exists = userMapper.exists(
            new LambdaQueryWrapper<UserModel>()
                .eq(UserModel::getPhone, phone)
        );
        if (exists) {
            throw new BizException(UserErrorCode.PHONE_ALREADY_EXISTS);
        }
    }

    /** 校验用户存在且状态可用，返回用户实体供后续使用 */
    public UserModel checkEnabledUser(Long userId) {
        UserModel user = userMapper.selectById(userId);
        if (user == null) {
            throw new BizException(UserErrorCode.USER_NOT_FOUND);
        }
        if (UserStatus.DISABLE.equals(user.getStatus())) {
            throw new BizException(UserErrorCode.USER_DISABLED);
        }
        return user;
    }
}
```

### 13.2 Assembler（复杂对象组装）

```java
/**
 * Convert  → 简单字段映射（MapStruct，无额外查询）
 * Assembler → 复杂组装（需要查询额外数据、多数据源聚合）
 */
@Component
@RequiredArgsConstructor
public class UserAssembler {

    private final UserConvert userConvert;
    private final RoleMapper roleMapper;
    private final DeptMapper deptMapper;

    public UserVO assembleVO(UserModel user) {
        UserVO vo = userConvert.toVO(user);

        // 补充部门名称
        if (user.getDeptId() != null) {
            DeptModel dept = deptMapper.selectById(user.getDeptId());
            vo.setDeptName(dept != null ? dept.getDeptName() : null);
        }

        // 补充角色列表
        List<RoleModel> roles = roleMapper.selectByUserId(user.getId());
        vo.setRoleNames(roles.stream().map(RoleModel::getRoleName).toList());

        return vo;
    }
}
```

## 十五、事务管理规范

### 15.1 事务边界：Command 层

```java
// ✅ 正确：事务加在 Command 的 execute 方法
@Transactional(rollbackFor = Exception.class)
public Long execute(CreateUserForm form) { ... }

// ❌ 错误：事务加在 Controller
@PostMapping
@Transactional
public Result<Long> create(@RequestBody @Valid CreateUserForm form) { ... }

// ❌ 错误：Mapper / Cache 粒度太细，无法覆盖完整业务操作
@Transactional
public void insert(UserModel user) { ... }
```

### 15.2 事件与事务的协调

```java
// 事务提交后再发布事件，避免"事务回滚 + 事件已发出"的数据不一致
private void registerAfterCommit(Runnable action) {
    TransactionSynchronizationManager.registerSynchronization(
        new TransactionSynchronization() {
            @Override
            public void afterCommit() {
                action.run();
            }
        }
    );
}
```

### 15.3 跨模块事务策略

```text
同一数据库  →  @Transactional 统一事务
跨数据库 / 跨服务  →  事件 + 最终一致性，不使用分布式事务
```

## 十六、异常处理规范

### 16.1 各层异常职责

| 层次 | 异常处理职责 |
|------|-------------|
| Infrastructure | 捕获技术异常，包装为 SysException 向上抛出 |
| Application | 业务规则不满足时，抛出 BizException |
| Adapter | 不捕获业务异常，由 GlobalExceptionHandler 统一处理 |

### 16.2 使用规范

```java
// ✅ 业务规则不满足
throw new BizException(UserErrorCode.USER_NOT_FOUND);

// ✅ 带自定义描述
throw new BizException(UserErrorCode.INSUFFICIENT_BALANCE,
    String.format("余额不足，当前: %s，需要: %s", balance, amount));

// ✅ 包装技术异常
try {
    ossComponent.upload(file);
} catch (Exception e) {
    throw new SysException(SysErrorCode.SYSTEM_ERROR, e);
}

// ❌ 禁止直接抛 RuntimeException
throw new RuntimeException("用户不存在");

// ❌ 禁止在 Controller 手动 catch 业务异常（破坏统一处理）
try {
    createUserCommand.execute(form);
} catch (BizException e) {
    return Result.fail(e.getCode(), e.getMessage());
}
```

## 十八、架构全景总结

### 18.1 各层职责一览

| 层次 | 定位     | 核心职责                  | 禁止事项 |
|------|--------|-----------------------|----------|
| Adapter | 入口层    | 协议适配、格式校验、路由分发        | 业务逻辑、事务、直接操作存储 |
| Command | 写操作层   | 业务规则、状态变更、事件发布        | 调用其他 Command、复杂查询 |
| Query | 读操作层   | 数据查询、结果组装             | 任何写操作 |
| Helper | 辅助层    | 可复用逻辑、复杂对象组装、组装设计模式落地 | 直接处理 HTTP、发布事件 |
| Model/Form | 操作入参层  | HTTP 入参接收、格式校验        | 包含业务逻辑 |
| Model/Query | 查询入参层  | HTTP 入参接收、格式校验        | 包含业务逻辑 |
| Model/DTO | 传输层    | 层间数据传递                | 包含业务逻辑 |
| Model/VO | 响应层    | 接口响应数据定义              | 包含业务逻辑 |
| Infrastructure/mapper | 数据库访问  | 只负责 SQL 执行            | 业务逻辑、缓存逻辑 |
| Infrastructure/cache | 缓存访问   | 封装 Key 和序列化           | 业务逻辑、直接访问 DB |
| Infrastructure/es | ES 访问  | 封装索引操作                | 业务逻辑 |
| Infrastructure/config | 模块配置   | 模块级 Bean 配置           | 业务逻辑 |
| Capability | 业务组件层  | 跨模块可复用业务能力            | 依赖具体业务模块 |
| Framework | 技术组件层  | 第三方 SDK 封装            | 引入业务概念 |
| Common | 公共业务模块 | 文件、字典、地域等通用接口         | 被其他业务模块代码依赖 |
| Support | 通用基础层  | Spring 生态通用能力         | 引入业务含义 |
| Base | 零依赖基础层 | 纯 Java 基础能力           | 依赖 Spring 等重框架 |

### 18.2 核心公式

```text
COLA-Lite  =

  COLA 分层思想           → 清晰职责边界
+ 六边形架构              → 统一外部入口
+ 轻量级 CQRS             → 读写职责分离
+ Form 直达 Application   → 简化入参对象，去除冗余转换
+ DTO 按需传递            → 层间数据传递，不污染 Form 和 VO
+ Helper 辅助模式         → 设计模式落地空间
+ 应用层自行组合存储       → 缓存、DB、ES 策略显式可见，无黑盒
+ 事件驱动                → 模块间松耦合

−

  DDD Aggregate Root      → 避免过度设计
− Repository 封装类        → 去除黑盒，应用层自行组合
− Event Sourcing          → CRUD 场景无需
− 读写库分离               → 普通场景无需
```

| 落地难度 | 易 | 难 | **易**            |
